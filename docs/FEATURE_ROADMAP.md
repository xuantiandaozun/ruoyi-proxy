# ruoyi-proxy 功能演进路线

本文记录当前产品边界、已完成基线和后续开发顺序。后续功能统一围绕任务协议建设，避免终端、Hub、调度器、飞书和 Web 各自实现权限、确认与审计。

## 已确认的产品边界

- Hub 是受信网络中的管理节点，集中持有 AI 配置和 Spoke 注册表。
- `/__hub__/v1/token` 保留匿名领取 15 分钟一次性 Token 的快速接入设计。前提是 Hub 域名不公开，且 `/__hub__/` 只对受信网络或受控来源开放；未来若支持公网 Hub，应在兼容 v1 的前提下增加可选的访问策略，不能破坏现有快速注册流程。
- Hub 管理端口只监听 `127.0.0.1:8001`；远程写操作必须经过 Hub 侧确认，Spoke 不开放远程管理入站端口。
- 文件同步不属于产品范围。发布文件由现有部署脚本、制品平台或外部传输工具负责，不再维护 `sync_config.json`、主从同步角色或同步命令。
- Hub/Spoke 不默认等同于蓝绿代理。节点可以只运行 AI 运维 CLI 或 `spoke-agent`，健康检查必须根据实际项目类型和服务档案执行。

## 当前基线（2026-07）

### 已完成

- [x] 蓝绿反向代理、多服务路由、环境切换、低内存部署和 HTTPS/Nginx 配置。
- [x] Agent 优先的交互式 CLI、斜杠命令目录、ReAct 工具执行、写操作确认和会话持久化。
- [x] Hub 集中 AI 网关、匿名短效 Token、Spoke 长期凭证、档案上报、吊销和 v1 兼容迁移。
- [x] Hub 统一远程任务协议：状态机、幂等、租约、取消/重试、结构化动作、批量/分组目标和事件审计。
- [x] Spoke 出站轮询、独立 `spoke-agent` 与代理内置 Worker 的所有权切换，避免重复领取任务。
- [x] Spoke 档案 v3、能力协商、资源/健康上报、Hub 节点治理和 `/hub-select` 默认目标。
- [x] MySQL 连接档案、配置发现、密码分离保存、结构浏览和受控 SQL 查询。
- [x] SQLite AI 定时任务、租约领取、读写权限边界、运行历史和 CLI/Agent 工具。
- [x] Hub 旧版注册流程、数据库、调度器和部分 Agent/CLI 行为的单元测试。

### 当前主要缺口

- M2 终端体验尚未完成：首页状态摘要、统一 theme/render、无颜色模式、长输出分页和 readline 安全异步通知仍待开发。
- 能力控制目前是节点级动作白名单，尚缺服务级能力范围、最低 Agent 版本约束和更细粒度角色权限。
- Windows 开发环境当前只可靠采集 CPU 数；内存和磁盘资源采集以 Linux 部署环境为准。
- 已建立 CI 和关键可靠性测试，CLI 主流程、跨平台脚本及端到端部署测试仍需继续补齐。
- 数据库暂只支持 MySQL，缺少结果脱敏、影响预估、PostgreSQL 和完整查询审计。

## 统一执行模型

```text
终端 / AI / 调度器 / 飞书 / Web
                 │
                 ▼
        Hub 结构化任务中心
                 │
        权限 → 确认 → 幂等
                 │
                 ▼
       本机执行器 / Spoke Worker
                 │
                 ▼
      事件、结果、审计与通知
```

任务至少包含：任务 ID、幂等键、发起人、来源渠道、目标节点/服务、结构化动作、风险级别、确认记录、状态、超时、创建/开始/结束时间、输出摘要和错误信息。

## 后续开发计划

### M0：可靠性与安全边界基线（最高优先级）

目标：先保证现有能力不会绕过确认、阻塞切换或在并发下暴露可变状态。

- [x] 重构 `run_shell` 只读识别：检测 `;`、`&&`、`||`、管道、重定向、子命令等控制结构；只有单一且完整匹配白名单的命令才免确认。
- [x] 为只读 Shell 分类增加表驱动测试，覆盖复合命令、大小写、空白、下载、服务控制和危险命令。
- [x] 代理仅在读锁内取得不可变路由快照，释放锁后再执行 `ServeHTTP`，确保 SSE/WebSocket 不阻塞切换。
- [x] `GetConfig` 返回深拷贝；配置保存失败时不污染内存状态。
- [x] 增加 HTTP Server、调度器和 Spoke Worker 的统一上下文与优雅退出。
- [x] 建立 CI：`gofmt`、`go vet`、`go test ./...`、Linux 构建；Linux 环境增加 `go test -race`。
- [x] 为 `internal/proxy`、HTTP 服务生命周期、确认边界和配置回滚补测试。

验收标准：复合 Shell 命令不能免确认；活动长连接不阻塞蓝绿切换；`go test -race` 无数据竞争；每次提交自动完成格式、静态检查、测试和 Linux 构建。

### M1：统一远程任务协议

目标：把当前远程 Shell 队列升级为后续调度器、渠道和 Web 都可复用的任务中心。

- [x] 明确任务状态机：`pending / claimed / running / succeeded / failed / timed_out / canceled`。
- [x] 增加客户端幂等键，重复请求只创建一个任务；同一键复用于不同载荷时拒绝请求。
- [x] 支持待领取任务取消、失败任务重试、领取租约过期恢复和最大尝试次数，并提供 Hub 管理 API 与 CLI 命令。
- [x] 增加结构化动作：状态、日志、重启、部署、只读数据库查询；原始 Shell 作为受控高级动作保留。
- [x] 支持单节点和多节点批量目标，记录每个目标的独立任务与结果。
- [x] 支持按 Hub 节点分组下发，并对组内每个目标保留独立结果。
- [x] 将确认人、确认时间、来源、动作摘要和状态变化写入随任务持久化的只追加事件审计。
- [x] 在不破坏 v1 端点和字段的前提下增加任务可选字段；旧 Spoke 仍可领取原始 Shell 任务并从 `claimed` 直接提交终态结果；结构化动作只下发给声明 v2 控制协议的新 Worker。

验收标准：相同幂等键不会重复执行；取消和重试行为可预测；Hub 重启后任务可恢复；旧 Spoke 注册和聊天契约测试继续通过。

### M2：节点能力与终端体验

目标：让 Hub 能准确选择节点、判断能力并稳定展示异步状态。

- [x] Spoke 上报 Agent/协议版本、操作系统、CPU、内存、磁盘、能力列表和服务端点健康摘要。
- [x] 增加 Hub 管理的别名、标签、环境、负责人、分组、维护状态和能力白名单；这些字段不会被 Spoke 心跳覆盖。
- [x] 增加 `/hub-select`，远程命令、结构化动作、任务查询和节点详情默认作用于当前节点，并在提示符与确认信息中回显目标。
- [ ] 首页展示当前角色、Hub 连通性、选中节点、待确认任务和当前会话。
- [ ] 建立统一 theme/render 层，支持状态徽标、宽度适配、无颜色模式和长输出分页。
- [ ] 异步任务通知通过 readline 安全刷新，不破坏用户正在输入的内容。

验收标准：Hub 能按标签和能力筛选节点；维护节点不会领取新任务；任何远程操作都明确显示实际目标和所需能力。

### M3：数据库安全与多驱动

目标：在现有 MySQL 能力上补齐生产数据库操作的保护措施。

- [ ] 增加 PostgreSQL 驱动、连接测试、Schema、字段和索引浏览。
- [ ] 为查询结果增加按字段名和规则配置的脱敏。
- [ ] `UPDATE`/`DELETE` 无条件语句强制二次确认；可行时先执行 `EXPLAIN` 或影响行数预估。
- [ ] SQL 分类器处理 CTE、注释、锁查询、存储过程和多语句边界。
- [ ] 记录连接档案、SQL 指纹、操作者、确认记录、耗时、影响行数和结果摘要，不记录明文密码。
- [ ] 增加连接最小权限检查和只读账户建议。

验收标准：MySQL/PostgreSQL 具有一致的查询体验；敏感字段默认不直接展示；高风险 SQL 无法通过普通一次确认执行。

### M4：集中定时任务

目标：让定时任务可以安全作用于 Hub 管理的节点和节点组。

- [ ] 扩展任务目标为本机、指定 Spoke 或节点分组。
- [ ] 增加输入快照、失败退避、最大重试次数和超时策略。
- [ ] 支持 `forbid / replace / allow` 并发策略。
- [ ] 高风险任务运行时叠加目标节点能力白名单和创建时的写权限授权。
- [ ] Hub 管理面增加任务 CRUD、运行历史和手动触发 API。
- [ ] 增加通知适配接口，先支持终端摘要，后续接飞书。

验收标准：多进程不会重复领取；失败重试有上限；目标离线时不丢任务；任务的每次运行都可追溯到配置快照和目标节点。

### M5：会话中心与任务关联

目标：将“对话意图”和“实际执行”分离，同时保持可追溯关系。

- [ ] 会话支持搜索、重命名、置顶、删除、导出和来源过滤。
- [ ] 工具细节进入可选执行记录视图，默认只展示真实用户/AI 对话。
- [ ] 会话消息引用任务 ID，任务审计不依赖聊天记录保存。
- [ ] Hub 保存跨节点会话，Spoke 本地会话继续支持离线。
- [ ] 补充密钥、数据库密码和工具输出的统一脱敏策略。

验收标准：删除会话不会删除任务审计；任一任务可追溯到发起会话和确认记录；导出内容不包含已识别的密钥。

### M6：飞书渠道

目标：在任务协议稳定后接入新的请求和通知渠道，不允许渠道直接执行 Shell。

- [ ] 以官方 `larksuite/cli` 作为可选运行时依赖，用 JSON 输出作为适配契约。
- [ ] 使用 `lark-cli event` WebSocket 将私聊映射到 Hub 会话。
- [ ] 默认仅允许私聊和用户白名单；群聊及高风险动作必须显式开启。
- [ ] 使用交互卡片或一次性确认码完成写操作确认，并写入统一任务审计。
- [ ] 支持任务完成、失败和超时通知；文档、表格、日历等出站操作先使用 `--dry-run`。

验收标准：飞书无法绕过 Hub 权限和确认；重复事件不会创建重复任务；渠道断线重连不会丢失已确认任务。

### M7：Web 管理端

目标：在任务、权限和审计协议稳定后提供可视化管理，不复制 CLI 业务规则。

- [ ] 节点、任务、调度、会话、数据库档案和审计查询页面。
- [ ] 所有写操作调用统一 Hub API，并复用相同的权限和确认模型。
- [ ] 增加登录、会话过期、CSRF 防护和最小角色模型。

验收标准：CLI、飞书和 Web 对同一任务返回一致状态；Web 不包含独立的执行或权限分支。

## 持续性要求

- **兼容性**：v1 的 `/__hub__/v1/token`、`register`、`profile`、`chat` 及既有字段保持兼容；协议升级只能增加可选字段或新端点。
- **测试**：每个缺陷先补回归测试；Hub 协议改动必须运行旧版注册迁移测试；关键并发逻辑必须通过 race 检查。
- **Secret 管理**：凭证文件使用 `0600`，日志、会话、任务输出和错误信息统一脱敏。
- **可观测性**：任务和远程调用带追踪 ID，关键状态变化使用结构化日志，并为失败率、延迟和队列深度预留指标。
- **发布门槛**：更新 CHANGELOG，验证 Hub/Spoke 两种构建，记录配置迁移和回滚方式。

## 推荐实施顺序

```text
M0 可靠性基线
  → M1 统一任务协议
    → M2 节点能力与终端体验
      → M3 数据库安全
      → M4 集中定时任务
        → M5 会话中心
          → M6 飞书渠道
            → M7 Web 管理端
```

M3 与 M4 可在 M1 状态机稳定后并行；M6、M7 必须等待任务权限、幂等和审计模型稳定，避免后期重复改造。
