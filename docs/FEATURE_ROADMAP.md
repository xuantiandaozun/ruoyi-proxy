# ruoyi-proxy 功能演进路线

本文把终端、Hub/Spoke、数据库、会话、定时任务和飞书统一到同一套任务与审计模型中，避免每个入口各自实现权限和执行逻辑。

## 产品角色

- Hub 管理员：查看节点、下发任务、管理权限与计划任务、审计结果。
- Spoke 运维者：注册本机、维护项目档案、决定节点可执行能力、查看本机任务。
- AI Agent：把自然语言转换为结构化任务，但不能绕过确认、权限和审计。
- 渠道用户：从终端、飞书私聊或后续 Web 管理端发起同一种任务。

## 统一执行链路

`终端 / 飞书 / 调度器 → Hub 任务中心 → 权限与确认 → Spoke 执行器 → 结果与审计 → 原渠道通知`

所有执行入口最终创建结构化任务。任务至少记录发起人、来源渠道、目标节点、动作、风险级别、确认记录、开始/结束时间、输出摘要和最终状态。

## Phase 1：远程管理与会话体验

- [x] Hub 创建远程命令任务，Spoke 通过出站轮询领取，无需开放 Spoke 入站端口。
- [x] Spoke 凭证校验、任务归属校验、超时、输出截断、结果持久化。
- [x] `/hub-exec <spoke-id> <command>` 下发任务，执行前强制确认。
- [x] `/hub-jobs [spoke-id]` 查看状态、输出和错误。
- [x] 管理端口仅监听 `127.0.0.1`，避免远程绕过 CLI 确认。
- [x] Spoke 可匿名领取短效一次性 Token；注册后立即采集服务器资料、公网 IP 和备注并提交 Hub。
- [x] 工具调用保留在模型上下文中，但不再产生空白 AI 输出层或可见历史。
- [x] `/load` 加载会话后回显真实用户/AI 对话。
- [x] 独立 `spoke-agent` 常驻执行模式，交互 CLI 与守护进程复用同一执行器。
- [x] Hub 根据最近心跳展示节点在线、空闲、离线和吊销状态。
- [ ] 节点版本、能力、CPU/内存/磁盘和服务健康摘要。
- [ ] 远程任务取消、重试、幂等键、批量节点和结构化动作（状态/日志/重启/部署）。

生产环境可使用 `/spoke-agent-install` 安装 systemd 服务，底层命令为 `ruoyi-proxy spoke-agent`；交互 CLI 仍保留兼容轮询。后续使用长轮询或 WebSocket 降低延迟与请求频率。

## Phase 2：终端与 Spoke 管理

- 建立统一 theme/render 层，集中管理颜色、表格、状态徽标、宽度适配和无颜色模式。
- 首页显示当前角色、服务、Hub 连通性、节点数、待确认任务数和当前会话。
- Spoke 支持别名、标签、环境、负责人、分组、维护状态、能力白名单和最后心跳。
- 增加 `/hub-select` 交互选择器，后续命令默认作用于所选节点。
- 日志与长输出采用分页/折叠，异步事件不破坏 readline 当前输入行。

## Phase 3：项目数据库管理

- [x] 以手动录入远程 MySQL 为主流程：连接独立归属于业务项目和环境，不依赖当前部署项目或技术栈，同一服务器可登记多个项目。
- [x] 用户可直接把连接资料交给 AI 保存，也可通过 `/db-add` 的密码隐藏向导录入；连接档案和密码分文件保存，密码文件权限为 `0600`。
- [x] 从指定项目目录发现 Spring `application*.yml/properties`、`.env`、JSON、TOML 和 Compose YAML 中的 MySQL 连接配置，作为可选辅助能力。
- [x] 提供 `/db-add`、`/db-discover`、`/db-list`、`/db-test`、`/db-schema`、`/db-query`，并接入 AI 数据库工具。
- [x] SELECT/SHOW/DESCRIBE/EXPLAIN 默认只读执行；写入、DDL、多语句、锁查询和 OUTFILE 操作进入确认流程。
- [x] 查询设置 30 秒命令超时和 200 行返回上限。
- 首期支持 MySQL/PostgreSQL，后续扩展 Redis；提供连通测试、库表浏览、字段/索引查看和只读查询。
- [ ] 增加 PostgreSQL、索引详情、结果脱敏、无条件更新删除二次确认、影响行数预估和完整审计。

## Phase 4：会话中心

- 会话列表支持搜索、重命名、置顶、删除、导出和按来源渠道过滤。
- 加载时默认展示真实对话，工具细节放入可选“执行记录”视图。
- 会话与任务分离：对话负责意图，任务负责执行；同一任务可从终端发起并在飞书收到结果。
- Hub 可保存跨节点会话，Spoke 本地会话继续支持离线使用。

## Phase 5：AI 定时任务

- [x] 使用独立本地 SQLite（`configs/scheduler.db`）保存任务与运行审计，不复用远程 MySQL 项目连接。
- [x] 任务包含名称、本机服务 ID、Cron/时区、AI 指令、超时、启用状态、权限和上下次运行状态。
- [x] 支持五段 Cron、`@every`、`@daily` 和 `@at RFC3339` 单次任务，以及暂停、恢复、删除、手动触发和历史查询。
- [x] CLI 与代理进程都可运行调度器，通过 SQLite 租约避免两个进程重复领取；单进程限制并发执行数量。
- [x] 默认任务只允许只读工具；`allow_write=true` 必须在创建或更新时确认，后台不会用缺失的弹窗绕过授权。
- [x] 提供 `/tasks`、`/task-add`、`/task-enable`、`/task-disable`、`/task-run`、`/task-history`、`/task-delete`，并接入 AI `scheduled_tasks` 工具。
- [ ] 扩展目标 Spoke/分组、输入快照、失败退避与重试、`forbid / replace / allow` 并发策略和通知渠道。
- [ ] 高风险任务运行时继续叠加目标 Spoke 能力白名单；Hub 管理面增加集中任务 API。
- 典型任务：每日健康巡检、日志异常摘要、证书到期检查、数据库慢查询报告和发布后验证。

## Phase 6：飞书渠道

采用官方 `larksuite/cli` 作为可选运行时依赖，不在项目内重写飞书 OpenAPI：

- 用 `lark-cli auth status` 做启动检查，以 JSON 输出契约解析结果。
- 出站适配：私聊/群消息、文档、表格、任务、日历；有副作用的命令先执行 `--dry-run`。
- 入站适配：使用 `lark-cli event` WebSocket 订阅，将飞书私聊映射到 Hub 会话。
- 默认只允许私聊和用户白名单；群聊、机器人身份和高风险动作显式开启。
- 飞书中的确认使用交互卡片或一次性确认码，确认记录写入同一任务审计。
- 渠道只负责收发，不能直接执行 shell；所有操作必须经过 Hub 任务中心。

## 横向能力

- RBAC 与能力策略：谁可以操作哪些节点、服务、数据库和动作。
- Secret 管理：凭证轮换、脱敏、最小权限和泄漏扫描。
- 审计与可观测性：任务事件、指标、结构化日志、失败告警和追踪 ID。
- 版本与兼容性：Hub/Spoke 协议版本、能力协商和滚动升级。
- Web 管理端：在任务协议稳定后再增加，复用同一 API，不复制业务规则。

## Hub/Spoke 向后兼容约束

- v1 的 `/__hub__/v1/token`、`register`、`profile`、`chat` 路径和既有字段保持不变。
- 协议升级只能增加可选字段；Hub 必须接受旧 Spoke 不包含新字段的请求。
- 新 Hub 必须继续加载旧版 `hub_spokes.json` 和单 Token 格式的 `hub_pending_token.json`。
- 新能力通过新端点或能力协商加入，不能让旧 Spoke 因未知能力而注册或对话失败。
- 每次改动 Hub 协议必须运行旧版注册流程契约测试。
- Spoke 档案带独立 `schema_version`；升级后自动补齐系统字段，只对缺失的用户字段运行增量引导并重新提交 Hub。
